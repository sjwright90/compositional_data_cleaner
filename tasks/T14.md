**Spec:** §6.4 step 1 and Gates (03-ingest-names); §5.3 (02-data-model); A3

## Implement
- **Stage `names_map`** (depends on `harmonize`; registered in `STAGES`; builder in `tests/arch_inputs.py`, `arch_vocab`-compatible).
- **Dictionary:** each ingest group (key values, row counts, sheets) maps to a known analyte, a custom analyte, or `EXCLUDE` (no unit/fraction needed; the pre-pivot filter), a fraction `D`/`T`/`N` (pre-filled from the T11c hint or `default_fraction`, always confirmed), a known or custom unit, and a variant (default empty).
- **Variants:** groups that map to the same analyte + fraction + unit and differ only by an extra ingest key are highlighted with "merge (default)" or "keep separate"; keep-separate sets editable short variant keys from the extra key values.
- **Dictionary upload:** a previous project's dictionary (with its custom analytes and units) pre-fills; conflicts with existing rows are shown and must be resolved. **Each custom analyte row in an upload is checked with `Vocabulary.check_new_analyte` and each custom unit row with `Vocabulary.check_new_unit`** before it is accepted: a blocked clash is shown and refused; a near match requires confirmation. Accepted rows are reported for T15's `Project` method to persist; this stage writes nothing.
- **Gates:** unmapped ingest groups; unassigned fractions; one ingest group mapping to conflicting entries across sheets; many-to-one merges shown with counts (allowed). Per-group gates use indexed paths and are matched by `IngestGroupKey.id()`, never by list position.
- **Data-dependent defaults:** the suggested dictionary (analyte, fraction, unit, variant per group) uses the T11a `Stage.suggest` mechanism; `accept_defaults` stores the resolved entries, never a sentinel.
- Interactive creation of custom analytes and units is T15; a group may reference an analyte or unit only if it is known at this point (shipped or project config), otherwise it stays unmapped.

## Done when
- A group mapped to `EXCLUDE` needs no unit or fraction and its rows are counted as excluded.
- `method` extra key from `project_basic`: "merge" yields one feature, "keep separate" yields two with distinct variants.
- Mn-D and Mn-T groups stay separate features (distinct fractions).
- An uploaded custom analyte whose name or alias collides with an existing one is blocked and the clash is in the report; a near match asks for confirmation; an uploaded custom unit that clashes is blocked; each path is tested through `check_new_analyte` / `check_new_unit`.
- A group mapped to different analytes on two sheets is reported as a conflict gate.
- Uploaded dictionary conflicts are listed and block until resolved.
- Stage `names_map` is in `STAGES`; architecture tests pass with `arch_vocab`.
- `./scripts/check.ps1` passes.
