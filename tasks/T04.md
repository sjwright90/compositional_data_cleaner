## Implement
- Pydantic row models for every §7 file; loader layering defaults + `<project>/config/` overrides; reload with before/after hashes.
- `Vocabulary`: `analyte()`, `unit()`, `conversion(frm, to, analyte)` (analyte-specific row before generic, else `None`), `snapshot(used)` with a `UsageTracker`; collision/alias validation helpers used by custom-vocabulary tasks later.
- `core/profiles.py`: `water` profile as data (required fields `location_id`, `sample_date`; default sample key; canonical sample types).
- Out of scope here: displaying the warning in the runner/status rail/summary header (T06, U0, T32 consume the report item).
- Config files are standard CSV/JSON with no comments; the loader never skips `#` lines or `_comment` keys. `config/defaults/README.md` explains the starter set; the empty `config/defaults/PLACEHOLDER` marker signals placeholder status. While it exists the loader emits a warning `ReportItem` ("using placeholder configuration") that `Project`, the runner, the status rail and the summary header surface (A9).
- `qa_thresholds.json` holds the default `min_obs_per_cell = 3`.

## Done when
- Tests load only `tests/fixtures/config/`; no test reads `config/defaults/`, except one test asserting the starter files parse and that the PLACEHOLDER marker produces the warning item (and its absence does not).
- Override layering, analyte-specific conversion precedence, alias-collision blocking and `snapshot(used)` containing only referenced entries are tested.
- Physical profile is not enabled; `water` profile requires `location_id` and `sample_date`.
