## Implement
- **Stage `names`** (depends on `convert`; its input is the T15 output, which carries the dictionary and conversion results so this stays a single-dependency stage; registered in `STAGES`; builder in `tests/arch_inputs.py`, `arch_vocab`-compatible).
- **Template:** default `{analyte_key}_{fraction}_{variant}_{unit_suffix}` from `tokens.json`; empty parts and their separators omitted; fraction omitted for `N` by default (template option); component order, separator and included parts configurable and stored in the recipe. Parts come from vocabulary keys, variant keys and unit suffixes only, never raw strings (invariant 5).
- **Pivot-key preview:** per feature, the raw ingest groups feeding it, row counts and the resulting column name, so the user can confirm Mn-D and Mn-T are separate.
- **Gates:** duplicate column names produced by the template (blocking item naming both features); many-to-one merges shown with counts; features without a target unit listed.
- Output: the name map keyed by `FeatureId.canonical()`; display names appear only here and at export.

## Done when
- Fixture config gives `mn_D_mgL`, `mn_T_mgL`, `mn_D_icp_mgL` (variant) and `ph_SU` (fraction `N` omitted).
- Changing the template order or separator changes the names and the stage fingerprint; the same recipe gives identical names on rerun.
- Two features that the template renders identically are reported as a blocking duplicate-name item listing both feature ids; the run does not commit.
- Every included feature in `project_basic` has exactly one target unit and exactly one unique name (asserted from the output).
- Stage `names` is in `STAGES`; architecture tests pass with `arch_vocab`.
- `./scripts/check.ps1` passes.
