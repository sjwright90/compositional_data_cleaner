## Implement
- **Stage `convert`** (depends on `names_map`; registered in `STAGES`; builder in `tests/arch_inputs.py`, `arch_vocab`-compatible).
- **Custom analytes:** fields of `known_analytes.csv`, pre-filled from the raw string (cleaned name, suggested key, raw string as alias, `transform = log`, `allow_negative = false`). **Creation calls `Vocabulary.check_new_analyte`**: a blocked clash is refused with the clash shown; a near match returns "did you mean …?" and requires confirmation. `Project.add_custom_analyte` (the only writer) appends a row with `source: user` to `<project>/config/known_analytes.csv` and logs it; stages reading the file become stale through `config_files`. Promotion export in the shipped schema.
- **Custom units:** the form has unit, unit class, `applies_to`, column suffix and optional conversion rows (generic or analyte-specific). **Creation calls `Vocabulary.check_new_unit`**; a blocked clash is refused with the clash shown. `Project.add_custom_unit` writes rows to the project's `known_units.csv` / `conversions.csv` with `source: user` and logs them. A custom unit with no conversion can only be its own target unit.
- **Target units:** one per feature (analyte + fraction + variant), restricted to the same unit class or to units reachable through an analyte-specific row. `applies_to: physical` units (e.g. `ppm`) are usable in a water project only through an explicit, logged project-level override that states the assumed equivalence. `S.U.` is its own class.
- **Convert:** value × factor + offset. Lookup order: analyte-specific (analyte, from, to) → generic (from, to) → unavailable (never guessed). DLs converted by the same rule. Basis conversions (NO₃ as N ↔ as NO₃, mg/L ↔ meq/L) exist only as analyte-specific rows. Each rule is reported with counts and an `analyte_specific` flag.
- **Gates:** missing target units; cross-class conversions with no analyte-specific row; basis-qualified units (as N, as CaCO₃) never merged without confirmation.
- **Feature ids (follow-up closed here for `FeatureId`):** this is the first task that constructs `FeatureId` (it needs the target unit). Add a validating factory in `core/ids.py` that checks analyte and unit against the `Vocabulary` and fraction against `Fraction`; the stage uses only the factory; T12's architecture test enforces it.

## Done when
- NO₃ as N → NO₃ as NO₃ uses the analyte-specific row (factor 4.426 in fixture config) and the report flags `analyte_specific = true`; a generic-only pair reports `false`.
- A conversion with no row is unavailable: listed as a gate, no value invented.
- DLs are converted with their values: an ND at DL 0.5 mg/L in ug/L has DL 500.
- `ppm` as a water unit is refused without the logged override; with it, accepted and logged with the stated equivalence.
- Creating an analyte whose name or alias collides is blocked via `check_new_analyte` (clash in the report) and a near match needs confirmation; creating a unit that clashes is blocked via `check_new_unit`; a custom unit with no conversion can only be chosen as its own target.
- The `FeatureId` factory rejects an unknown analyte or unit; a planted direct `FeatureId(...)` in `core/` fails the architecture test.
- Stage `convert` is in `STAGES`; architecture tests pass with `arch_vocab`.
- `./scripts/check.ps1` passes.
