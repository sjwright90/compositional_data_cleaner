## Implement
- Pydantic recipe tree: one section per stage, `schema_version`, source paths + SHA-256, embedded config snapshot (`Vocabulary.snapshot`), per-project settings (`min_obs_per_cell` value used).
- Gate fields: a typed `Gate` value that is unresolved, an explicit decision, or `{"accept_default": true}`; stages declare their gate fields.
- Migrations scaffold chained by version; one stored-old-recipe test per migration.
- `Project`: `run_stage`, `preview`, `staleness`, `commit`, `needs_attention`; the only writer of logs, checkpoints (`<project>/checkpoints/<ts>_<stage>/`) and manifest; decision log rows from report items (`type` incl. `default-accepted`).
- `core/run.py`: `python -m core.run --project <dir> [--recipe <file>] [--accept-defaults]`; runs registered stages in order, stops at the first unresolved gate and lists all unresolved gate fields; `--accept-defaults` writes explicit `accept_default` entries into the output recipe and logs them as default-accepted.
- Runner output includes a "using placeholder configuration" line when the loader reports the PLACEHOLDER warning (A9).
- All stage stubs registered by later tasks must return a report; here: two trivial test stages only.

## Done when
- Recipe round-trips; a stored old-version recipe migrates and logs the migration.
- Every registered stage returns a report and `Project` writes one log row per report item.
- Commit creates an immutable checkpoint with a manifest (file, rows, cols, SHA-256, fingerprint, recipe hash, config hash, versions); recommit creates a new one.
- Running `core.run` on `tests/fixtures/generated/project_basic` with unresolved gates exits non-zero and prints the unresolved gate fields; with `--accept-defaults` those entries appear in the output recipe.
- `./scripts/check.ps1` passes.
