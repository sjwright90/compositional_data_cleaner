## Implement
- **Registration.** Add `ContractStage` to `core/stages.py::STAGES` and a builder to `tests/arch_inputs.py` returning `(inputs, params)` that resolve against `tests/fixtures/config/` (`arch_vocab`-compatible): a `SourceFile` pointing at the committed `tests/fixtures/arch/contract_min.csv` (a header line and two data rows; hand-written, not generator output), so the arch tests need neither temp files nor the generator. The path is resolved from the repo, so it works from any cwd. `config_files`: `tokens.json`, `known_analytes.csv`, `known_units.csv`, `header_rules.csv`. `depends_on = ()` (root; inputs are the verified source copies from T10).
- **Params** (frozen pydantic): `sheets: dict[str, SheetContract]` keyed `"<source posix path>::<sheet>"` (sheet name `""` for csv). Each: `include: bool = True`, `layout: Gate[SheetLayout]` (shape long/wide, transpose, header cleanup, numeric locale, column roles) declared `gate_field(..., suggested=True)`. Keys are stable decision ids (invariant 3); gate paths read `contract.sheets[lab_a_long.xlsx::long].layout`.
- **Suggestion (T11a mechanism):** `ContractStage.suggest(inputs, params, vocab)` detects each sheet's layout deterministically and returns `{"sheets[<key>].layout": SheetLayout}`. `accept_defaults` stores that resolved `SheetLayout`; drift is a comparison with the current suggestion (source SHAs are in the fingerprint, so it changes only when the data does).
- **Seeding:** `sheets` entries are created from the T10 inventory by `seed_sheets(params, sources)` (new entries get an unresolved layout; sheets whose source vanished are reported, not removed). `Project.import_sources` and the runner apply it through an optional stage hook `sync_params`; the plan shows the exact hook.
- **Output** `ContractResult` (frozen dataclass of DataFrames): `sheets` (one row per included sheet: resolved shape, transpose, locale, header row, first data row), `columns` (one row per column: source, sheet, position, raw header, cleaned header, role, analyte, fraction, unit, parse_status, candidates), `cells` (long string frame: source, sheet, row, col, text) so T12 gets cell data without reading files. The plan states the memory cost measured on `project_basic`, and the alternative if it is too large.
- **Header parser (`core/headers.py`)**, per A16(a)(b):
  - enumerate every right-to-left split of the cleaned header on `Tokens.header_separator` into unit, optional fraction code and analyte; a split is valid when the unit is a unit alias (or key) in the vocabulary, the fraction is a `fraction_codes` entry (or absent), and the analyte is a vocabulary name, key or alias; the unit part may be absent only for an analyte with `dimensionless`;
  - exactly one valid split → use it; fraction absent → `AnalyteRow.default_fraction`, else a **blocking** item (never guess);
  - more than one → **blocking** item naming the header and each candidate split;
  - zero → try the `header_rules.csv` regexes (§6.2 fallback); if none match, the column is `unresolved` and shown with only config-resolved hints (unit alias, fraction code) and the raw remainder, never fuzzy matches;
  - a header that resolves to analyte [+ fraction] with no unit and a non-dimensionless analyte → **blocking** "missing unit" item;
  - every outcome counted in a `ReportItem` (parsed, defaulted fraction, fallback, unresolved, blocked).
- **Row blocking (A16(d)).** The first data row is the first row below the header with at least one non-blank metadata cell whose analyte cells are not all non-result text. Any row between the header and it is a non-data row: **blocking** item naming the file, sheet and 1-based row and saying "put all header information on the header line". Known limit, stated in the docstring: a labelled DL row with numeric cells and a non-blank first cell looks like a data row and is caught later by the location gate (T13).
- **Blank rows (exception to A16(d)):** a fully blank row (every cell empty) between the header and the first data row is skipped and counted in an info item, never blocked; any row with a non-blank cell that is not a data row still blocks.
- **Other §6.2 items in scope:** roles pre-filled from `column_role_keywords`/`metadata_keywords`; header cleanup preview (before/after) in the report; numeric-locale detection reported with the evidence; transpose flag.
- **Confirm and record in decisions.md (first real stage):**
  - input convention: root stage gets `tuple[SourceFile, ...]`, one dependency gets that output, more than one gets `dict[dep, output]`; first multi-dependency stage is named when known;
  - cache-supported output types are exercised for real: frozen dataclass of DataFrames round-trips through the Parquet cache with a string-only `cells` frame;
  - the fate of `header_rules.csv`: kept as the fallback described above.
