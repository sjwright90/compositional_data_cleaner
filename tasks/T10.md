## Implement
- **Logging rule (explicit, approved):** `Project.import_sources` writes its audit-log row immediately, because importing is an explicit, disk-mutating user action. Project construction, `run_stage` and `preview` stay write-free; recipe-load and config notices are still logged at commit (T06c). Log the rule in `docs/decisions.md`.
- `Project.import_sources(paths) -> tuple[ReportItem, ...]`:
  - **first**, check every path's extension case-insensitively against `.xlsx` / `.csv` (A17) before touching disk; any unsupported file raises a `ProjectError` subclass listing each one with "save it as .xlsx or .csv", and nothing is imported;
  - copies each file into `<project>/sources/` through a temp file in the same folder, then rename; same name and same SHA-256 → no copy plus an info `ReportItem`;
  - same name, different content → copy as `<stem>_2<ext>` (then `_3`, …) plus a warning `ReportItem` naming both files;
  - copies are never modified;
  - the recipe stores the project-relative posix path and SHA-256 of the copy; the original absolute path and import time go only into the immediate audit-log row (one row per imported file);
  - then calls `set_sources` with the in-project copies. `set_sources` keeps accepting only in-project paths and `build_recipe`'s outside-project error is unchanged.
  - **One consistent action:** order is copy (temp + rename), then the updated recipe written atomically (temp + `os.replace`), then the audit row. A crash after the copy leaves a file in `sources/` that the recipe does not list; the next import of that file re-adds it (see Done when). `import_sources` therefore also writes the recipe.
- **Source verification:** before cache lookup in `Project._run`, a stage with `depends_on == ()` re-hashes every source copy; if a SHA differs from the recipe, raise a `ProjectError` subclass whose plain message names the file, the recorded and the found SHA-256 prefix, and says the copy was changed after import. A missing copy gets its own plain message. (The run cannot proceed, so it raises rather than reports.)
- `core/ingest.py`:
  - `read_inventory(path) -> tuple[SheetInfo, ...]` (frozen dataclass: file, sheet, rows, cols, preview frame of the first N rows) for `.xlsx` and `.csv` only (A17; a csv has one sheet named `""`); N from a module constant documented in the file, not config;
  - `read_sheet(path, sheet) -> DataFrame` with everything as strings so T11/T12 own parsing. Rule, documented in the module docstring: numeric cells → shortest round-trip repr (`1.374` → `"1.374"`, no float noise); date/datetime cells → ISO 8601 date, with the time only when non-midnight; text unchanged; empty → `""`;
  - a locked file raises the existing `FileLockedError` message ("open in Excel"); an unreadable or corrupt file raises a `ProjectError` subclass naming the file and likely cause. Neither shows a traceback.
- Golden test pinning the root `{params, sources}` fingerprint payload (`Project._fingerprint_of`) for a stub root stage with two sources.
- Not stored in the recipe: project name and project type. §6.1 lists them as user decisions (`03-ingest-names.md` line 9) but no section T10 names requires them in the recipe (§6.1 "Done when" requires only source paths and hashes); the project-name consumer is the summary header (`07-summary-export.md` line 36, T32). Record this in PROGRESS.md as a T32/T33 follow-up.

## Done when
- Importing the same file twice: one copy, an info item, and the recipe lists the file once; importing a different file of the same name: `<stem>_2<ext>` exists, warning item names both, the first copy's bytes are unchanged; a third gives `_3`.
- The recipe holds only project-relative posix paths and SHA-256; `recipe_hash` is identical for two projects at different absolute locations that import identical files.
- After `import_sources`, `log/decisions.jsonl` has one row per file with the original absolute path and an import timestamp; constructing `Project`, `run_stage` and `preview` change no file (byte-identical tree).
- Editing a source copy then running a root stage raises the plain message naming the file; restoring the bytes lets the run pass; the check runs before the cache is consulted.
- Golden fingerprint test passes and fails when the payload shape changes.
- Re-importing a file that is present in `sources/` but missing from the recipe re-adds it with an info item and one audit row; a fresh `Project` opened after an import lists the source in its recipe (no in-memory state needed).
- `read_sheet` on generated `lab_e_wide.xlsx` gives `"1.374"`-style numbers without float noise, `"2023-07-03"` for dates, `"<0.005"`, `"NM"` and `""` for the blank cell (exact cells asserted).
- An import containing a `.xls` file (also `.XLS`, `.parquet` or any other unsupported extension) is refused with the plain message listing each unsupported file and "save it as .xlsx or .csv": no file copied, no recipe change, no log row, even when the other files in the call are valid.
- `read_inventory` returns names, dimensions and previews for a multi-sheet xlsx and a csv from `project_basic`; a locked file (monkeypatched `PermissionError`) gives the plain "open in Excel" message; a corrupt xlsx gives the plain message naming the file.
- No data problem in `core/ingest.py` raises a bare `ValueError`/`KeyError`.
- `./scripts/check.ps1` passes.
