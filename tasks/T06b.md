## Implement
- `core/audit.py` (pure):
  - `LogRow` dataclass with the §8 fields: `decision_id`, `timestamp`, `stage`, `type` (user / auto-applied / default-accepted / uploaded / undo / migration), `action`, `target`, `parameters`, `rows_affected`/`items_affected`, `evidence_file`, `warnings`, optional `rationale`.
  - `rows_from_report(stage, report, type, ...)`: one row per report item.
  - Append-only **JSONL** writer/reader helpers. §8 specifies fields but no file format, so JSONL is the choice; record it in decisions.md.
- `Project(root, stages=STAGES, defaults_dir=DEFAULT_CONFIG_DIR)`:
  - Loads config with `config_layers`/`load_config`, builds `Vocabulary`.
  - **Typed params only:** `Project` and the runner only ever see typed Params objects obtained through `load_recipe` (never raw recipe dicts). Gate-default drift warnings and migration items from `load_recipe` go to the log.
  - `run_stage` (cache by fingerprint; Parquet under `cache/`), `preview` (no cache write, no log, no commit), `staleness`, `commit`, `needs_attention` (returns `[]`, documented stub; matching is T52).
  - `staleness`: passes `depends_on` and recomputed fingerprints to `compute_staleness`. Gates are not modelled there.
  - `commit`: one log row per report item, plus an immutable checkpoint directory `checkpoints/<timestamp with ms>_<stage>_<first 8 chars of fingerprint>/` holding stage outputs and evidence CSVs. Never overwrite: raise if the directory exists. Recommit creates a new directory.
  - `manifest.json` per checkpoint: file, rows, cols, SHA-256, stage fingerprint, recipe hash, config hash, app version, Python/pandas/numpy/scikit-learn versions.
  - Only `Project` writes logs, checkpoints, cache and the manifest.
  - Surface the loader's `placeholder_config` warning item (A9) in the log and via a property the runner reads.
- Stage registry is injected (`stages=`), so tests register two trivial stages (defined under `tests/`, one with a `Gate` field) without touching `core/stages.py` or `ARCH_INPUTS`.
- `core/run.py`: `python -m core.run --project <dir> [--recipe <file>] [--accept-defaults]`, `main(argv, stages=STAGES)`.
  - Runs stages in topological order of `depends_on`; stops at the first stage with an unresolved gate and lists ALL unresolved gate fields across stages (`<stage>.<dotted.path>`).
  - Default recipe path `<project>/recipe.json`; output recipe is written to the same path or `--recipe`.
  - `--accept-defaults`: help text says "tests only (A3)"; the runner prints a warning every time it is used. Writes explicit `{"accept_default": true, "value": ...}` entries via `accept_defaults` and logs them with `type = default-accepted`.
  - Prints a "using placeholder configuration" line when `Config.placeholder` is true (A9).
  - Exit codes, each with a plain-language message and documented in `--help`: `0` success, `2` unresolved gates, `1` error (locked file, bad recipe, unsupported recipe version, etc.). No tracebacks for expected failures.

## Done when
- Every registered stage returns a report and `Project` writes exactly one log row per report item.
- Commit creates an immutable checkpoint with a complete manifest; recommit creates a new directory; an existing directory raises; checkpoint files are untouched by the recommit.
- Staleness reflects a param change and a config-file change.
- Runner tests generate `project_basic` into `tmp_path` via `tests.fixtures.generate` (not a pre-generated directory). With the gated test stage and unresolved gates: exit 2 and all unresolved gate fields printed. With `--accept-defaults`: exit 0, warning printed, explicit entries in the output recipe, `default-accepted` log rows.
- Placeholder-config line appears in runner output when the marker exists.
- `python -m core.run --help` shows exit codes.
- `./scripts/check.ps1` passes.

## Amendments (approved after the first implementation; checkpoint review 1)
1. `cache/heads.json` holds the latest committed fingerprint per stage and is written only by `Project.commit()`. `run_stage` and `preview` never touch heads; `staleness()` uses heads as "stored". Test: `run_stage` without commit leaves the stage not DONE.
2. The runner skips the commit when the stage fingerprint equals `heads[stage]` and prints `<stage>: unchanged, not recommitted`. `Project.commit()` itself always creates a new checkpoint. Test: two runner runs give one checkpoint per stage.
3. At commit, one log row per gate field: `type = user` for an explicit decision, `type = default-accepted` for an `accept_default` entry, value in `parameters`. Both types tested.
4. Cache writes go to a temp dir and are renamed atomically. An unreadable or incomplete entry is a miss with a warning `ReportItem`. Tested.
5. `core/audit.py` is pure (serialisation only); all file I/O is in `Project`.
6. The `--help` test runs `sys.executable -m core.run --help`.
7. Amendments are recorded here; 1–3 (and the rest) are logged in `docs/decisions.md`.
